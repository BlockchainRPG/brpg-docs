# V6.0.0 Release Notes

V6.0.0 is a major milestone. We're launching the **BlockchainRPG Dashboard** — a brand-new way to play — bringing **party boss fights** to the game, and unifying the entire client + service stack under a single platform.

---

## 🚀 Headline: The Dashboard Launches

We're thrilled to introduce the **BlockchainRPG Dashboard** — a modern, web-native client for managing your characters and playing the game.

- **Built fresh** on Next.js + Chakra UI for a responsive, accessible, fast experience on both desktop and mobile browsers.
- **Inventory, crafting, hunting, boss fights, fusion, salvage, healing, summoning, marketplace** — all the core gameplay loops are first-class.
- **Wallet authentication** via UAL with Anchor and Wombat integrations.
- **Daily quests, sticker book progress, boss-fight tracking**, and reward flows built into the experience.
- **Profile pages** for inspecting any player's characters and progress.
- Runs alongside the existing Classic Unity client — pick whichever experience you prefer.

The dashboard is a parallel path, not a replacement. Classic stays. Your account, characters, and progress are the same — both clients talk to the same on-chain contract.

---

## ⚔️ Party Boss Fights

The party combat introduced for hunts in V5.22.0 now extends to bosses.

- **Dispatch a party of up to 5 characters** against a boss in a single transaction.
- Combat resolves as **pair-duels**: characters take on the boss one at a time in order; when one falls, the next steps up.
- The boss takes **cumulative damage** from the whole party. Unkilled bosses persist their HP loss for the next group — even a wipe chips away at the boss.
- **All loot goes to the party leader** (the owner of the dispatched characters).
- Cooldowns: 5 minutes for survivors, 60 minutes for characters that fall — same rules as party hunts.
- The dashboard now offers **5 boss party slots** and a refreshed result screen that shows each character's outcome side-by-side.

## 🏗️ Unified Platform

V6.0.0 is also a major architectural milestone — the entire client + service stack is now unified under a single monorepo.

- **Classic Migration**: the legacy Unity-embedded React client (`brpg-ui`) is now `apps/classic` inside the platform monorepo. Same gameplay, shared tooling, shared types, and shared deployment pipeline.
- **brpg-chat as a first-class app**: the in-game chat service joins the monorepo with shared CI, shared dependencies, and consistent infrastructure.
- **Centralized API layer**: login, contract reads, transaction submission, and trace parsing all share a common retry + error layer for predictable behavior under network issues.
- **Hedged endpoint requests**: critical reads now fan out to multiple endpoints in parallel and use the first successful response, reducing tail latency and improving reliability.
- **AI agent documentation**: `AGENTS.md` files across the monorepo give AI coding assistants the context they need to safely contribute changes.
- **Auto-purge of stale D1 transactions**: the API database automatically cleans up old transaction records to keep storage tight.

## 🧱 Contract Refresh

The on-chain game contract got a cleanup pass.

- **`charequip` is now the canonical equip action.** It replaces `charequip2`, which is retained as a backward-compatibility wrapper for older clients.
- **`bossparty` powers boss combat.** Both solo and party boss fights now resolve through the same unified `huntdata::calculateBattle` engine that powers hunts (minimum-1-damage floor, integer-turn resolution, rounded HP). The older `bossfight` action is kept as a thin wrapper for backward compatibility.
- **Removed deprecated contract actions** to keep the on-chain surface lean.
- **Self-hosted CI runner** for the contract build pipeline — faster, more reliable releases.
