# V6.0.0 Release Notes

V6.0.0 is a major milestone. We're launching the **BlockchainRPG Dashboard** — a brand-new way to play — bringing **party boss fights** to the game, and unifying the entire client + service stack under a single platform.

---

## 🚀 Headline: The Dashboard Launches

We're thrilled to introduce the **BlockchainRPG Dashboard** — a modern, web-native client for managing your characters and playing the game.

- **Built fresh** on Next.js + Chakra UI for a responsive, accessible, fast experience on both desktop and mobile browsers.
- **Inventory, crafting, hunting, boss fights, fusion, salvage, healing, summoning, marketplace** — all the core gameplay loops are first-class.
- **Wallet authentication** via UAL with Anchor and Wombat integrations.
- **Daily quests, sticker book progress, boss-fight tracking**, and reward flows built into the experience.
- **Profile pages** for inspecting any player's characters and progress.
- Runs alongside the existing Classic Unity client — pick whichever experience you prefer.

The dashboard is a parallel path, not a replacement. Classic stays. Your account, characters, and progress are the same — both clients talk to the same on-chain contract.

---

## ⚔️ Party Boss Fights

The party combat introduced for hunts in V5.22.0 now extends to bosses.

- **Dispatch a party of up to 5 characters** against a boss in a single transaction.
- Combat resolves as **pair-duels**: characters take on the boss one at a time in order; when one falls, the next steps up.
- The boss takes **cumulative damage** from the whole party. Unkilled bosses persist their HP loss for the next group — even a wipe chips away at the boss.
- **All loot goes to the party leader** (the owner of the dispatched characters).
- Cooldowns: 5 minutes for survivors, 60 minutes for characters that fall — same rules as party hunts.
- **Both clients support party play:** the dashboard offers **5 boss party slots** with a refreshed result screen showing each character's outcome side-by-side, and Classic now has its own **multi-character hunt/boss select** with party slots, full-party validation, and a "characters automatically deselect after a fight" flow so you can queue the next batch immediately.

## 🏗️ Unified Platform

V6.0.0 is also a major architectural milestone — the entire client + service stack is now unified under a single monorepo.

- **Classic Migration**: the legacy Unity-embedded React client (`brpg-ui`) is now `apps/classic` inside the platform monorepo. Same gameplay, shared tooling, shared types, and shared deployment pipeline.
- **brpg-chat as a first-class app**: the in-game chat service joins the monorepo with shared CI, shared dependencies, and consistent infrastructure.
- **Centralized API layer**: login, contract reads, transaction submission, and trace parsing all share a common retry + error layer for predictable behavior under network issues.
- **Hedged endpoint requests**: critical reads now fan out to multiple endpoints in parallel and use the first successful response, reducing tail latency and improving reliability.
- **AI agent documentation**: `AGENTS.md` files across the monorepo give AI coding assistants the context they need to safely contribute changes.
- **Auto-purge of stale D1 transactions**: the API database automatically cleans up old transaction records to keep storage tight.

## 🧱 Contract Refresh

The on-chain game contract got a cleanup pass.

- **`charequip` is now the canonical equip action.** It replaces `charequip2`, which is retained as a backward-compatibility wrapper for older clients.
- **`bossparty` powers boss combat.** Both solo and party boss fights now resolve through the same unified `huntdata::calculateBattle` engine that powers hunts (minimum-1-damage floor, integer-turn resolution, rounded HP). The older `bossfight` action is kept as a thin wrapper for backward compatibility.
- **Removed deprecated contract actions** to keep the on-chain surface lean.
- **Self-hosted CI runner** for the contract build pipeline — faster, more reliable releases.

## 🎮 Unity Client Improvements

- **Multi-character party select** — the Hunt / Boss popup now spawns 5 party slots and lets you tap-to-toggle characters into your party. Selected cards highlight via the existing focus ring; once the party is full, non-party cards become non-interactable so you can't accidentally tap past the limit. Tapping a filled slot removes that character.
- **`BossParty` action wiring** — Classic dispatches the new `BossParty` event end-to-end through the JS bridge → React handler → contract, with per-character HP and cooldown updates applied locally as soon as the result returns.
- **Auto-clear party after results** — once a hunt or boss result is shown, the party slots empty automatically so you can queue another batch without manually deselecting. A failed transaction (wallet cancel, chain reject) leaves the selection intact for retry.
- **Self-hosted CI runner** for Unity WebGL builds.
- **jslib modernization** — migrated all plugin bridges from the legacy `ReactUnityWebGL` global to `dispatchReactUnityEvent`.
- **Addressables URL fix** — dynamic assets now load reliably.
- **Death cooldown handling** brought in line with the contract's actual windows.

## 🛠️ Maintenance & Security

- **Contract deploy split** into separate `set code` + `set abi` transactions — the combined `set contract` crossed WAX's 512 KB `max_transaction_size` cap with the new wasm. Splitting keeps each transaction comfortably under the limit so deploys land cleanly.
- **WAX RPC proxy** now surfaces the upstream chain error body when every endpoint returns a 5xx, instead of swallowing it as a generic "proxy failed" — far more useful when debugging a rejected transaction.
- Major dependency bumps including Next.js, Vite, ESLint, Vitest, jsdom, Wrangler, and Node 25 → 26 for the chat service.
- Security-driven dependency updates across the monorepo.
- GitHub Actions workflow upgrades (`actions/checkout`, `docker/login-action`, `docker/build-push-action`, `cloudflare/wrangler-action`).

## 🐛 Bug Fixes

- **Hunt CURRHP can no longer go negative.** When a killing blow overshot a character's remaining HP, the chain stored a slightly negative value (e.g., `-2`) because the battle calc skipped the zero-floor on the hunt path. CURRHP is now floored at 0 before being persisted, matching the boss path.
- **Boss party result popup** now shows real per-character max HP looked up from the local roster — dead characters used to display `0 / 1` because the popup was using a `remaining + 1` heuristic.
- **Dashboard hunt party size** was capped at 1 character due to a typo (`Math.min(raw, 1)` instead of `Math.min(raw, 5)`) — V5.22.0 promised multi-character hunts in the release notes but the dash UI silently shipped a single-character cap. Now 5 as intended.
- Fixed a latent edge case where a player's first damage entry against a freshly summoned boss could fail on lookup (the boss damage map now safely defaults to 0 for new attackers).
- Last-hit detection on `bossparty` now keys off `bossRemainingHp <= 0` instead of `battleResult.leftWon` — fixes a rare mutual-kill case where both the boss and the final party member fell on the same turn, which previously skipped the last-hit reward and saved the boss with `CURRHP = 0`.
- Boss combat now validates that every party member belongs to the same owner — defensive check for the contract self-auth path.
- Reward-roll loop now floors `minDamageForReward` at 1, preventing a CPU-DoS on hypothetical sub-100 MAXHP bosses.
- Various stability fixes across hunts, equips, and boss fights.
